# AGENTS.md — правила для агента (docker-lab, вариант B)

Учебный сервис Launch Control (FastAPI). Задача — привести в порядок упаковку в образ,
не меняя поведение приложения. Списка дефектов нет: их надо найти инструментами.

## Границы
- Работай только в каталоге `docker-lab`. Команды — из его корня.
- `app/` и `tests/` — не менять никогда. `scripts/bench.sh` сам временно дописывает строку
  в `app/main.py` и откатывает её; это единственное допустимое касание, и только скриптом.
- `scripts/score.sh`, `scripts/bench.sh`, `scripts/tools.sh`, `scripts/.gitignore` — не менять.
- Не создавать `.hadolint.yaml`, не использовать `hadolint --ignore`, не «улучшать» табло.
- `pyproject.toml` — можно править только список зависимостей; код `app/` не должен от этого зависеть.
- `README.md` не трогать до отдельного шага «README».
- Никаких `sudo`, установки пакетов на хост, `docker login`, `docker push`, `docker system prune`,
  `docker volume prune`, правок `~/.docker`.
- Не трогать чужие образы/контейнеры. Удалять можно только свои теги `launch-control:*` и `lc-*`.
  Удаляй точные пути/теги, без wildcard (`docker image rm -f launch-control:step2-slim`, а не `launch-control:*`).
- Никаких `git push`, `git reset --hard`, переписывания истории, чужих веток.

## Критерий готовности (DoD)
1. `./scripts/score.sh optimized` → `9/9`.
2. `./scripts/smoke.sh launch-control:optimized` → exit 0.
3. `uv run --frozen --extra dev pytest -q` → все тесты проходят.
4. `hadolint --no-color Dockerfile` → 0 error, 0 warning (info допустимы).
5. Размер ≤ 400 MB; тёплая пересборка после правки `app/main.py` — секунды.
6. В образе нет root, компилятора, dev-инструментов, тестов, секретов; есть HEALTHCHECK.
7. Поведение эндпоинтов не изменилось.

## Измерения и доказательства
- `bench.sh` принимает **только тег**: `./scripts/bench.sh <tag>`. Флаг `-f` он не поддерживает
  (второй аргумент игнорируется) — варианты измеряются только сменой `Dockerfile` и git-тегами.
- `BASELINE_MB=...` в `score.sh` не используется — не передавай.
- Корневой `bench-results.md` **не** игнорируется git (паттерн в `scripts/.gitignore` действует
  только внутри `scripts/`) — коммить его как доказательство.
- В системе стоит `/etc/uv/uv.toml` с внутренним индексом (Nexus). Поэтому:
  локальные запуски — `uv run --frozen ...`; пересборка lock — только
  `uv lock --default-index https://pypi.org/simple`; перед коммитом проверяй
  `grep -n 'vs-nexus' uv.lock` (должно быть пусто) и что source = `https://pypi.org/simple`.
- Baseline снимается один раз, до правок и до создания `.venv`.
- Не переписывай `bench-results.md` и `evidence/` руками — только фактические выводы команд.
- Любое утверждение подтверждай фактическим выводом команды, не пересказом.
- Если проверка недоступна (нет сети/инструмента) — остановись и сообщи, не обходи.

## Стиль
- Минимальные diff'ы, без «улучшений на будущее» и без правок вне запрошенного шага.
- Комментарии в Dockerfile — по-русски, по делу.
- После шага отчёт: что изменено (diff), какие команды запущены, фактический вывод,
  какой пункт табло/инструмент это подтверждает. Без коммита, пока не попросили.
